validated download, completing the workflow end to end.

## Acceptance criteria

- Load only the owner's clinics (including inactive) and private validated template
  bytes/version. Show filename and actual PDF immediately after selection, including
  incomplete forms; blank invalid/missing fields, calculate only from valid gross.
  No manual preview-update button.
- Handle loading, no clinics/template, fetch/generation/render error and retry.
  Link empty/missing-template states to Clinics. Retain entered values on failure
  and explain unavailable actions without fake success.
- Preview/every download action share an immutable input/template-version snapshot.
  Immediately invalidate old readiness/bytes upon input/clinic/template changes,
  before async work. Ignore stale success/error responses, including delayed A
  after choosing B. Old responses cannot override newer status. Never present stale
  bytes as current during fetching, pending or error.
- Enable download only when all required values are valid and the generated PDF
  matches the current inputs and selected template. Form/toolbar buttons share the rule. Track PDF
  generation freshness independently of viewer-specific load events; do not add a
  new business requirement that download waits for a particular renderer callback.
  Disable download during an update and after any current fetch, generation or
  rendering error; retain inputs for retry.
  Filename is `<four-digit number> <clinic name>.pdf`: pad only filename number,
  sanitize incompatible characters, preserve other spaces/accents/casing. Open
  downloaded PDF and verify flattening and original invoice number inside.
- Test two-session template replace/remove refresh: invalidate selection and pending
  work across tabs/navigation. Reconcile restored drafts with current template/data
  revisions and session policy; never restore obsolete generated bytes as current.
- Clean up object URLs/listeners and any workers actually used. Verify the
  chosen renderer and any required assets in the production build. Sign-out/account
  switch removes private bytes, preview cache and private byte references; cached data cannot leak across users. The chosen read
  contract is authenticated/no-store, not presigned reads. No client service secrets.
- Preserve Activity landing, shared navigation/monthly scope and existing clinic
  saves. Production uses real data only. Keyboard access, responsive preview and
  loading/error feedback follow existing controls/Alexandria.
